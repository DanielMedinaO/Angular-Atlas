Laboratorio A · Change Detection Explorer

Change Detection evalúa bindings y aplica al DOM los cambios necesarios. Con Zone.js, Angular puede iniciar la sincronización tras tareas asíncronas interceptadas. En Zoneless, Angular se apoya en notificaciones como eventos de la plantilla, nuevos inputs, señales leídas por una vista y markForCheck(). Un temporizador que solo escribe una propiedad ordinaria carece por sí solo de esa notificación.

En Angular 22, OnPush permite omitir vistas limpias. Un nuevo input, un evento en su subárbol o un cambio de una señal que la vista consume pueden hacer que participe. Eager comprueba la vista cuando el recorrido alcanza su rama en un pase que la incluya. Eager no agenda por sí solo un pase ni fuerza el recorrido de antepasados OnPush.

Suma una lectura en un hijo, prueba el temporizador y actualiza el padre. Compara qué contadores avanzan. Ejecuta npm start para ver los contadores de desarrollo. Estos registran evaluaciones de la plantilla, incluso pasadas adicionales de verificación si se ejecutan. Una evaluación puede terminar sin cambios en el DOM. La instrumentación escribe el diagnóstico tras el render sin modificar señales.

computed() conserva el resultado de su última evaluación y vuelve a calcularlo al leerlo tras invalidar sus dependencias. Aquí el producto es simple. La misma técnica ayuda cuando el cálculo cuesta más o se consulta varias veces. 

readonly readings = signal(0);
readonly pages = computed(() => this.readings() * 24);

// OnPush es el valor predeterminado de @Component.
// El otro hijo declara esta opción en su decorador.
changeDetection: ChangeDetectionStrategy.Eager

Laboratorio B · List Rendering y @for

Marca el primer título en ambas listas e invierte el orden. Con track book.id, la marca sigue al libro. Con track $index, la marca sigue a la posición y puede aparecer en otro título. Al invertir, Angular puede reutilizar las mismas instancias y sus nodos en ambas listas. Comprueba los identificadores de instancia y los totales registrados en ngOnInit y ngOnDestroy.

Agrega o elimina un título y filtra por «Angular». Al agregar, el filtro se limpia para mostrar el nuevo título. Si el filtro retira una vista, el estado local de esa instancia se pierde al destruirla, incluso con una clave estable. Reserva $index para colecciones estáticas o casos donde la posición sea la identidad.

Un filtrado o una ordenación costosa invocados directamente desde el template pueden repetirse cada vez que se evalúa el binding. El catálogo usa computed() para reutilizar el filtro mientras el catálogo y la consulta se mantengan. 

visibleBooks = computed(() => filterBooks(this.books(), this.query()));

<!-- Identidad del libro -->
@for (book of visibleBooks(); track book.id) { … }

<!-- Identidad de la posición -->
@for (book of visibleBooks(); track $index) { … }

Laboratorio C · @defer

Explora 365 días de lecturas simuladas en tres categorías. Cambia entre anillo y pastel para comparar la proporción de cada categoría en el intervalo. Abre la tabla para consultar los valores diarios. Chart.js viaja con el gráfico en el chunk diferido.

Descargar resuelve el código del componente. Renderizar crea la instancia y su vista cuando se activa el bloque. @if condiciona la vista. @defer puede además separar dependencias standalone que solo se referencian dentro de bloques diferidos. loadComponent y loadChildren difieren un componente de ruta o una configuración de rutas. @defer difiere una sección de la vista ya navegada.

  • viewport se activa cuando el elemento observado entra en la ventana visible.
  • interaction responde a clic o teclado en el elemento disparador.
  • hover responde al puntero o al foco en el elemento disparador.
  • idle espera una oportunidad de inactividad del navegador.
  • when activa el bloque cuando una expresión se vuelve verdadera. La activación es irreversible.

Prefetch en idle puede reducir la espera después del clic. Consume ancho de banda y puede competir con otras solicitudes, incluso si el gráfico nunca se abre. Ambos escenarios comparten el código del gráfico. Recarga entre experimentos para reiniciar el módulo. 

<!-- #showChart identifica el botón disparador. -->
@defer (on interaction(showChart); prefetch on idle) {
  <app-performance-reading-chart />
} @placeholder {
  <p>Gráfico pendiente de interacción.</p>
} @loading {
  <p>Cargando gráfico…</p>
} @error {
  <p>No se pudo cargar el gráfico.</p>
}
  1. Ejecuta npm run build y sirve dist/angular-atlas/browser con un servidor estático con fallback a index.html. Abre /performance, entra en Chrome DevTools → Network, activa Disable cache y filtra por JS.
  2. Recarga la página con DevTools abierto. En Interacción, espera antes de pulsar «Mostrar gráfico». Identifica la solicitud al pulsar usando Initiator y el nombre del chunk en el build.
  3. Recarga de nuevo, elige prefetch en idle y espera la solicitud. El placeholder debe seguir visible hasta pulsar el botón. Con throttling puedes observar el estado de carga cuando la petición sigue pendiente.

Laboratorio D · Performance Profiling

  1. Angular DevTools Profiler. Ejecuta npm start. Inicia una grabación en Profiler, cambia el contador o filtra el catálogo y detén la captura. Selecciona un ciclo para inspeccionar componentes y hooks. Repite la misma interacción antes y después de mover un cálculo de la plantilla a computed().
  2. Chrome DevTools Performance. Graba una interacción aislada. En Main revisa las tareas largas y los eventos de scripting, layout y pintura. Usa Bottom-up y Call tree para localizar funciones de filtrado, ordenación o formateo que se repiten. Conserva los mismos datos, configuración de CPU y pasos al comparar capturas.
  3. Network. Examina el waterfall, Initiator, tamaño transferido y tamaño del recurso. Separa la carga inicial, la navegación y la interacción. Las cifras de transferencia del CLI son estimaciones y la red muestra el comportamiento del servidor observado.
  4. Bundles de producción. Ejecuta el comando de abajo y abre dist/angular-atlas/browser-stats.json en el visualizador de esbuild. Inspecciona outputs, sus imports dinámicos y bytesInOutput para identificar entradas grandes sin sumar un chunk compartido más de una vez.
  5. Build Budgets. En angular.json, configura architect.build.configurations.production.budgets. Usa initial para el arranque y anyComponentStyle para CSS por componente. Fija una advertencia que deje margen sobre el tamaño medido y un error que bloquee la regresión. 
npx ng build --configuration production --stats-json
