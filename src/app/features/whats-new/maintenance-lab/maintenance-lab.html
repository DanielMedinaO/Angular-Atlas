Versiones, soporte y compatibilidad

Major
Puede incluir cambios incompatibles. Planifica una versión mayor a la vez.
Minor
Incluye mejoras compatibles. Revisa también las dependencias pares.
Patch
Corrige errores conservando la compatibilidad de las APIs públicas estables.

La política vigente prevé una versión mayor al año con 12 meses de soporte activo y otros 12 meses de soporte a largo plazo (LTS). Durante LTS, Angular publica correcciones críticas y de seguridad según su política. Las APIs obsoletas tienen un período de transición. Por ejemplo, cambia NgIf por @if y comprueba la fecha de retirada en el changelog. Política de soporte y obsolescencia.

Angular 22 admite Node.js ^22.22.3 || ^24.15.0 || ^26.0.0, TypeScript >=6.0.0 <6.1.0 y RxJS ^6.5.3 || ^7.4.0. La auditoría de Atlas del 26 de noviembre de 2026 encontró Node.js 24.20.0, TypeScript 6.0.3 y RxJS 7.8.2 con Angular 22.2.5 y CLI 22.2.6. Matriz oficial de compatibilidad.

Ensayo de actualización

ng version muestra la instalación local. ng update sin paquetes permite consultar actualizaciones disponibles. Los siguientes comandos son ejemplos para una terminal local. Sustituye la versión objetivo tras consultar la guía. 

git status --short
npx ng version
npm run build
npx ng test --watch=false
git switch -c mantenimiento/angular-22-3
npx ng update
npx ng update @angular/core@22.3 @angular/cli@22.3
npx ng test --watch=false
npx ng build --configuration production

ng update puede ejecutar migraciones publicadas por los paquetes para adaptar código y configuración. Revisa el diff y valida también Material, CDK y Aria. Aria 22.2.7 requiere CDK 22.2.7, por lo que cualquier cambio de CDK debe comprobarse junto con Aria. Guía de actualización por versiones · Referencia de ng update.

Rollback con Git

Guarda los cambios de la rama de ensayo antes de volver a la rama de origen con git switch -. Si el cambio ya se compartió como un commit ordinario, crea un commit inverso con git revert <commit-de-actualización>. Reinstala las dependencias de la revisión restaurada y repite las validaciones. Para reproducir el árbol exacto usa npm ci con un lockfile guardado para esa revisión. Atlas ignora actualmente package-lock.json, así que conserva una copia del lockfile antes del ensayo.
