HTTP y recursos reactivos

Consulta Open Library y compara Observables, Signals y recursos de Angular con laboratorios ejecutables. Las peticiones reales usan solo los campos requeridos y un máximo de 10 libros.

HttpClient, GET y POST

HttpClient es el cliente HTTP inyectable de Angular. Sus métodos devuelven Observables fríos: la petición comienza al suscribirse, cada suscripción puede iniciar una nueva petición y desuscribirse cancela la petición en curso cuando el transporte lo permite. La respuesta se tipa desde TypeScript, pero ese tipo genérico no valida el JSON recibido; por eso el servicio de este laboratorio recibe unknown y normaliza la respuesta en tiempo de ejecución.

Observable, RxJS y Signals

toObservable() expone los cambios de un Signal como un flujo; aquí debounceTime(350) agrupa la escritura, distinctUntilChanged() evita repetir términos iguales y switchMap() cancela la búsqueda anterior cuando llega la siguiente. catchError() conserva el error como un estado visible. toSignal() adapta el último estado al template y gestiona la suscripción con el ciclo de vida del componente.

  • idle: todavía no hay una búsqueda válida; se requieren dos caracteres.
  • loading: la búsqueda remota está pendiente.
  • success: se recibieron libros.
  • empty: la API respondió correctamente sin coincidencias.
  • error: falló la red, la API o la validación del JSON.

Usa resource() cuando tu loader asíncrono trabaje naturalmente con Promise; rxResource() cuando la fuente ya sea un Observable; y httpResource() para peticiones HTTP con integración directa de HttpClient, opciones de solicitud e interceptores. Para una acción de usuario que modifica datos, POST/PUT/PATCH/DELETE con HttpClient y un flujo explícito suelen ser más adecuados: los recursos representan datos reactivos de lectura y pueden volver a cargarse al cambiar sus parámetros.

Interceptores funcionales y DI

Un interceptor recibe una solicitud inmutable y una función que continúa la cadena. Puede clonar la solicitud, observar la respuesta o gestionar errores antes de delegar al siguiente interceptor. El orden de withInterceptors([...]) define el orden de entrada; la respuesta recorre la cadena de vuelta. Las funciones se ejecutan en el contexto de inyección configurado, por lo que pueden usar inject() para servicios. Este logger registra método, URL sin parámetros, estado y duración; no imprime cabeceras, cuerpos ni términos de búsqueda.

El navegador necesita que Open Library permita CORS. Si la API no está disponible o responde con límites de uso, la interfaz muestra el error; no se usa un proxy ni un bypass. Activa fixtures locales para explorar los estados sin red.
