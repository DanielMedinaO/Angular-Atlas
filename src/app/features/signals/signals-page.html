Signals

Los signals son contenedores de valor que notifican a Angular cuándo cambian, permitiendo una detección de cambios granular sin depender de Zone.js.

Creando un signal

La función signal() crea un valor reactivo con un estado inicial. Se lee invocándolo como función, count(), y se actualiza con set() o update(), nunca mutando el valor directamente.

  • set(valor) reemplaza el valor por uno nuevo, sin importar el anterior.
  • update(fn) recibe el valor actual y devuelve el siguiente; úsalo cuando el nuevo estado depende del anterior.
  • Si el valor nuevo es igual al actual (Object.is), el signal no notifica a sus consumidores. 
const count = signal(0);

count();         // 0
count.set(5);     // reemplaza el valor
count.update(v => v + 1); // deriva el nuevo valor del anterior

Derivando estado con computed()

computed() crea un signal de solo lectura cuyo valor se recalcula de forma perezosa cada vez que alguna de sus dependencias cambia, manteniendo la lógica de derivación pura y predecible.

Las dependencias se descubren automáticamente: son los signals que se leen durante la ejecución de la función. El resultado se guarda en caché y solo se recalcula cuando alguna de esas dependencias cambia y alguien vuelve a leerlo. Además, las dependencias se reevalúan en cada cálculo, por lo que las ramas condicionales que no se ejecutan no generan dependencias. 

const count = signal(0);
const doubled = computed(() => count() * 2);

doubled(); // se recalcula solo cuando "count" cambia

linkedSignal(): derivado, pero escribible

linkedSignal() calcula su valor a partir de una fuente, igual que computed(), pero además permite escribir en él con set() y update(). Cuando la fuente cambia, el valor se recalcula y puede decidir si conserva la selección anterior mediante el parámetro previous.

La diferencia con computed(): un computed() es de solo lectura y siempre refleja su derivación; un linkedSignal() acepta una sobrescritura manual que dura hasta que su fuente vuelve a cambiar. Es la herramienta adecuada para estado local que depende de otro, como una selección dentro de una lista filtrada.

effect(): efectos secundarios, no estado

effect() ejecuta código cuando cambian los signals que lee. Su propósito es sincronizar la aplicación con el exterior: persistir en localStorage, escribir en el DOM manualmente, registrar analítica o trabajar con una librería de terceros.

No debe usarse para copiar estado de un signal a otro: para eso existen computed() y linkedSignal(), que son más simples y evitan ciclos de actualización. En el explorador, un effect() guarda la categoría y, al recargar, el valor se lee y se valida antes de usarse.

Signals frente a RxJS

Un signal representa un valor actual: siempre existe, se lee de forma síncrona y Angular sabe qué vistas dependen de él. Un observable representa un flujo de eventos en el tiempo: puede no emitir nunca, es asíncrono por naturaleza y requiere suscripción.

Usa signals para el estado de la interfaz y RxJS para flujos asíncronos con operadores como debounceTime, switchMap o peticiones HTTP cancelables. toSignal() y toObservable() permiten combinarlos.

Comunicación entre componentes

Los datos viajan hacia abajo (padre → hijo) mediante entradas y los eventos suben hacia arriba (hijo → padre) mediante salidas. El padre es el dueño del estado; el hijo solo recibe valores y avisa de lo que el usuario pide. Cuando ambos necesitan compartir un mismo valor editable, model() combina los dos sentidos.

  • input() / input.required(): dato de solo lectura, padre → hijo.
  • output(): evento hijo → padre; el valor llega como $event.
  • model(): valor bidireccional enlazado con [(propiedad)].

input() e input.required()

input() crea un signal de solo lectura con valor por defecto. input.required() no tiene valor inicial: el compilador exige que el padre lo enlace, de modo que nunca se lee un dato inexistente.

output() y $event

output<T>() declara un evento tipado. El hijo llama a emit() y el padre lo escucha con (evento)="metodo($event)", donde $event es exactamente el valor emitido. El hijo no conoce la lista de lectura: solo comunica una intención. 

{{ outputApiSnippet }}

model() y two-way binding

model() es un signal escribible que Angular expone también como entrada y como salida (favoriteChange). Con [(favorite)]="isFavorite" el padre pasa su signal y cualquier set() o update() del hijo lo actualiza, y viceversa.

Comparación con @Input(), @Output() y EventEmitter

Las APIs tradicionales siguen funcionando, pero usan propiedades mutables, requieren sincronizar manualmente la salida con el estado y dependen de RxJS para emitir. Las funciones modernas son signals: se integran con computed() y effect(), validan en compilación las entradas obligatorias y reducen el código repetitivo.
