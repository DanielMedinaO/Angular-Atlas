Conceptos y ejemplos

1. Reactive Forms: estado explícito

FormControl representa un valor, validadores y estados de interacción. FormGroup compone controles tipados y FormArray administra colecciones. El componente conserva la fuente de verdad; el template enlaza con formControlName. Implementación: reactive-form-lab/. 

const form = fb.nonNullable.group({
  title: ['', [Validators.required, Validators.minLength(3)]],
  year: new FormControl<number | null>(2026, [
    Validators.required, Validators.min(1450), Validators.max(2026),
  ]),
  additionalAuthors: fb.array<FormControl<string>>([]),
});

Usa setValue() para proporcionar el objeto completo, patchValue() para actualizar una parte y reset() para restaurar valores y estados. Los botones del laboratorio ejecutan esas tres operaciones.

2. Signal Forms: FieldTree y enlazado

Signal Forms, estable desde Angular 22, conecta un modelo signal() con form(). El resultado es un FieldTree cuya forma refleja el modelo: cada nodo expone estado reactivo y puede enlazarse a un control con FormField y [formField]. No es un FormGroup ni se modifica con métodos de Reactive Forms. Implementación: signal-form-lab/. 

const model = signal({ title: '', year: 2026 });
const bookForm = form(model, schema(path => {
  required(path.title);
  minLength(path.title, 3);
  min(path.year, 1450);
}));

<form [formRoot]="bookForm">
  <input [formField]="bookForm.title" />
</form>

El laboratorio lee value(), valid(), invalid(), touched(), dirty(), errors() y pending() desde los estados de campo. Las reglas personalizadas y las validaciones incorporadas viven en un esquema tipado.

3. Validación asíncrona y envío

Reactive Forms utiliza AsyncValidatorFn; cada valor nuevo cancela la suscripción anterior y su resultado tardío se ignora. Signal Forms usa validateAsync(), apropiado para un repositorio simulado que no necesita HTTP. Su recurso aborta validaciones obsoletas. Ambos muestran pending, duplicados y errores de comprobación. 

validateAsync(path.isbn, {
  params: ctx => ctx.value() ? { isbn: ctx.value() } : undefined,
  factory: params => resource({
    params: () => params(),
    loader: ({ params }) => repository.isDuplicateIsbn(params.isbn),
  }),
  onSuccess: duplicate => duplicate ? [{ kind: 'duplicate' }] : undefined,
  onError: () => [{ kind: 'unavailable', message: 'Reintenta la comprobación.' }],
});

FormRoot intercepta el submit y ejecuta submission.action. La opción ignoreValidators: 'none' bloquea el action mientras hay validaciones pendientes. La API también mantiene submitting() y rechaza envíos concurrentes. El laboratorio Reactive aplica la misma protección con su estado de guardado.

4. Campos dinámicos y persistencia

Reactive Forms agrega y elimina controles mediante FormArray. Signal Forms refleja el arreglo del modelo y obtiene los nodos correspondientes del FieldTree. Cada fila de ambas listas se renderiza con un identificador estable y su campo es obligatorio. El DTO de creación es independiente del modelo editable; un repositorio local en memoria guarda libros durante la sesión. 

// Reactive Forms
authors.push(fb.control('', Validators.required));
authors.removeAt(index);

// Signal Forms: actualizar el modelo; no usar FormArray aquí
model.update(value => ({
  ...value,
  additionalAuthors: [...value.additionalAuthors, ''],
}));

El ISBN duplicado se comprueba en un conjunto local de demostración. La comprobación de cliente mejora la experiencia, pero nunca sustituye la validación definitiva del backend.

¿Cuándo elegir cada enfoque?

Aspecto Reactive Forms Signal Forms
Estado Árbol de controles y Observables. Modelo signal y estado signal por campo.
Validación Funciones ligadas a controles. Esquema declarativo y validadores reutilizables.
Ventaja Maduro, ampliamente conocido y con APIs detalladas. Menos sincronización manual y mejor integración con Signals.
Consideración Más coordinación entre controles, suscripciones y vistas. API reciente; revisar compatibilidad de ecosistema y patrones de equipo.
Recomendación Ideal para aplicaciones existentes y equipos que dependen de su ecosistema. Buena opción para formularios nuevos en Angular 22 con equipo preparado.

Para un proyecto empresarial nuevo en Angular 22, elegiría Signal Forms si la versión y sus APIs estables están aprobadas por la organización y el equipo puede establecer patrones y pruebas. Mantendría Reactive Forms donde haya controles de terceros, integraciones o convenciones existentes que lo hagan más fiable; ambas opciones siguen siendo válidas.
