Dependency Injection

La inyección de dependencias (DI) permite que Angular entregue a cada pieza de la aplicación las colaboradoras que necesita, con un ciclo de vida y un alcance explícitos.

¿Qué problema resuelve?

Un componente que crea por su cuenta un catálogo, un logger o un cliente HTTP queda acoplado a esa implementación y decide también cuándo crearla. DI separa ambas decisiones: el consumidor declara qué necesita y un inyector resuelve qué instancia darle. Así varias partes pueden compartir estado, cambiar implementaciones en pruebas o recibir valores de configuración sin construir manualmente toda la cadena.

Crear con new o pedir con inject()

Quién se encarga de crear y compartir la dependencia

const catalog = new BookCatalog() private readonly catalog = inject(BookCatalog)
Cada llamada puede crear una instancia nueva; hay que ensamblar a mano sus dependencias y compartir la instancia. El inyector elige una instancia según los providers y la jerarquía activa.
Útil para valores puros que no dependen del ciclo de vida de Angular. Útil para servicios con dependencias, estado compartido, configuración o sustituciones de prueba.

Declarar servicios

@Injectable({{ '{' }} providedIn: 'root' {{ '}' }}) es la forma conocida de registrar un servicio en el inyector raíz. Angular 22 ofrece @Service() como API moderna con provisión automática equivalente para el caso común.

@Service({{ '{' }} autoProvided: false {{ '}' }}) mantiene la clase inyectable, pero no la registra automáticamente. Entonces hay que proveerla explícitamente, por ejemplo en providers de una ruta o de un componente. Es la opción de los contadores scoped de este laboratorio.

Árboles de inyectores y alcance

Angular combina dos jerarquías. Los EnvironmentInjector se organizan desde el inyector raíz hacia providers de rutas y entornos; los ElementInjector aparecen en elementos/componentes cuando declaran providers. Una búsqueda empieza cerca del consumidor y avanza por sus ancestros; si no encuentra el token en el árbol de elementos, continúa en el entorno. El provider más cercano gana.

  • Root: un provider automático crea una instancia compartida por toda la aplicación.
  • Route: cada configuración de ruta crea un entorno descendiente; sus componentes comparten ese provider, pero otra ruta con el mismo token obtiene otro.
  • Component: un provider en el componente crea una instancia en su inyector de elemento; cada instancia del componente recibe la suya.

La salida de una ruta no implica que su instancia se destruya inmediatamente: el Router puede conservar su inyector asociado a la configuración. No uses la navegación como garantía de limpieza; verifica explícitamente la política de vida útil que necesites.

InjectionToken y estrategias de provider

Una interfaz TypeScript desaparece al compilar a JavaScript, así que no existe un objeto en tiempo de ejecución que Angular pueda buscar. InjectionToken<T> sí es un objeto real y conserva la ayuda de tipos para el valor esperado.

  • useValue: entrega un valor existente, ideal para configuración.
  • useClass: construye una implementación asociada al token.
  • useFactory: calcula la dependencia, incluso a partir de otras dependencias.
  • useExisting: crea un alias al mismo objeto ya registrado, no una copia.

Contexto de inyección y NG0203

inject() funciona durante la creación de una clase administrada por Angular, por ejemplo en un inicializador de propiedad, constructor, factory de provider o dentro de runInInjectionContext(). Un handler de clic ocurre después, sin ese contexto: llamar ahí a inject() produce NG0203. Inyecta antes y usa la referencia guardada desde el handler.

Servicios bajo demanda con injectAsync()

injectAsync() devuelve una función que resuelve el servicio cuando se invoca. El cargador usa un import() dinámico y el servicio debe tener provisión automática (@Service() o providedIn: 'root'). En Chrome DevTools, abre Network, filtra por JS y presiona «Generar informe»: el chunk del exportador debe aparecer solo tras la acción. No se debe importar estáticamente su clase desde esta página.
